# 生成并检查一份配置

本练习只生成和检查 JSON 模板，不会加密、解密或修改你的文件。建议把练习文件保存到临时目录，例如 `C:\HSE-practice`。路径中的示例内容可以保留；本练习不会执行它。

## 你将完成什么

- 从主 GUI 生成一份加密配置模板。
- 看懂模板中最常见的路径、口令来源和安全模式字段。
- 在 GUI 中检查配置，并区分“配置格式有效”和“任务已成功执行”。

## 第一步：生成模板

1. 打开主程序，在顶部选择“生成配置”。
2. “密码表保存方式”先保留默认的“推荐安全：少保存一份密码表”。这个选项决定批量任务保存密码表的方式；它不是单文件密码强度或 HSE2 格式选择。
3. “配置用途”选择“加密配置”。解密任务应生成解密模板，不能把加密模板当作解密配置。
4. 在“保存为”中指定临时位置，例如 `C:\HSE-practice\encrypt-example.json`。如文件夹尚不存在，请先在资源管理器中创建它。
5. 点击“生成配置文件”。这只会写出 JSON 文件；不会读取示例输入路径，也不会启动加密。

## 第二步：认识模板字段

用记事本打开刚生成的 JSON。默认强化模式的加密模板包含以下主要字段：

| 字段 | 作用 | 修改时注意 |
|---|---|---|
| `sources` | 要处理的文件或文件夹列表 | 换成真实输入前，确认每条路径确实存在；路径要和口令映射中的键一致 |
| `source_passwords` | 每个输入对象的口令来源 | 示例从环境变量读取。变量名只是名字，不会自动创建变量或设置口令 |
| `metadata_password` | 读取/保护本批次辅助材料所需的口令来源 | 它可能与每个文件的口令不同；恢复时需要记得对应关系 |
| `output_dir` | 输出目录 | 改成一个有足够空间且你能找到的目录 |
| `batch_id` | 这次批次的识别名称 | 便于区分任务；不要把它当作密码 |
| `security_mode` | 记录所选密码表保存方式 | 应与所选模板相符；不要只为消除警告而随意改值 |
| `individually_encrypted_files_by_folder` | 指定文件夹内需要单独加密的相对路径 | 仅在确实需要文件夹内部单独加密时使用，并确认相对路径拼写正确 |
| `folder_inner_passwords` | 上述文件夹内单独加密文件的口令来源 | 路径必须对应上面的文件夹与相对文件路径 |

模板中的 `D:/data/...`、环境变量名和 `*-example` 批次名都是示例。环境变量 provider 仅说明“从哪里取值”；真正执行前还要在启动 GUI 的环境中设置相应变量。不要把真实口令粘贴进 JSON、教程、截图或日志。

## 第三步：检查配置

1. 回到主程序，选择“检查配置”。
2. “配置用途”选择“加密配置”，与刚生成的模板一致。
3. 选择 `encrypt-example.json`，结果格式可保留默认 JSON。
4. 点击“检查配置”，在结果中找到 `valid`。对于刚生成且未手动修改的默认强化加密模板，预期为 `true`、`issues` 为空。

如果你已经改过字段，出现问题时先检查 JSON 标点、字段拼写、配置用途和密码 provider 的结构。报告中的 `warning` 表示需要理解并处理的提醒；`issue` 是配置检查发现的问题。查看建议并修正后再检查。

## 这次检查能证明什么

`valid: true` 表示配置符合当前检查器所执行的配置规则。它**不表示**输入路径存在、环境变量已设置、密码正确、输出磁盘有足够空间，也不表示加密或解密已经运行成功。检查配置不会读写配置里指定的业务文件。

要真正执行批量任务：先复制模板并填写实际输入/输出路径，准备好配置引用的口令来源；随后使用“文件加密”或“文件解密”中的“运行已有配置”。执行前先用[批量加密与解密练习](batch-practice.md)熟悉样例流程，并保留输入原件。验证、配置检查和实际加解密是不同步骤。

## 安全模式的入门说明

生成器的选项只是在选择批量密码表的保存方式：

- **简单兼容：保存完整密码表**：更强调兼容性并保存完整密码表材料。密码表仍是敏感材料，应受保护并与公开分享隔离。
- **推荐安全：少保存一份密码表**：减少一类密码表材料，适合按模板提供的口令来源恢复。它不会替你保管环境变量或口令。
- **最高隐私：不保存密码表**：不写密码表；恢复时需要你正确保存并提供所需口令。丢失口令可能导致无法恢复。

三个选项都不会自动创建、轮换或备份口令，也不改变 v5 双视图格式的公开性质。若你不能可靠保管恢复所需的口令，不要仅凭“最高隐私”几个字选择模式；先用虚构文件完成批次练习。

## 完成标准

- 你能在生成后找到 JSON 文件，并解释 `sources`、`source_passwords`、`metadata_password` 和 `output_dir` 的用途。
- 你能在“检查配置”中选择正确用途，并读出 `valid`、`issues` 与 `warnings`。
- 你知道检查通过不等于加密成功，也没有执行本练习中的示例路径。
