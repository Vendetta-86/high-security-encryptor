# 新手术语索引

这里用日常语言解释界面和文档中常见名词。内部实现以对应格式说明为准；这些解释不构成独立密码学审查。

## 文件加密基础

| 名词 | 是什么、用途与大致处理方式 | 需要知道的限制 |
|---|---|---|
| 明文 | 加密前能直接阅读的原始内容。 | 文件名、路径和其他文件系统信息是否加密，取决于具体功能。 |
| 密文 | 加密后不可直接阅读的输出内容。 | 仍可能暴露文件大小、时间或文件存在事实。 |
| 加密 / 解密 | 加密用口令保护内容；解密验证所需凭据并恢复可读文件。 | 忘记口令可能无法恢复；加密不等于备份。 |
| 文件夹包 / `.zip.hse` | 把一个文件夹及内部目录结构保存成单个加密归档文件。 | 解密会恢复到新目录；应根据日志确认实际输出位置并保留输入原件。 |
| 口令 | 用户输入的秘密，用来导出或解锁密钥。 | 不要复用真实账户密码，也不要写入命令行历史。 |
| 随机数 | 加密需要的不可预测数据，由程序和系统安全随机源生成。 | 不要复制旧值或自行编造。 |
| salt（盐值） | 与口令一起用于密钥派生的随机公开数据。 | 盐值不是密码，也不能替代强口令。 |
| nonce（唯一数） | 某些算法每次加密所需的唯一输入值。 | 不要手工复用或修改；让程序管理。 |
| 认证加密 / 认证标签 | 加密同时检测密文是否被改动；标签是在解密时检查的数据。 | 检查失败时应视为恢复失败，不要忽略错误。 |
| KDF / Argon2id | KDF 将口令加工为加密密钥；Argon2id 是项目可使用的一种算法。 | 参数会影响计算时间和内存；按产品提供选项使用。 |
| chunk / 流式处理 | 大文件分成小段逐段处理，不必一次装入内存。 | 目标磁盘仍需要足够空间；分块不会隐藏文件大小。 |
| 退出码 | 命令结束时返回给 PowerShell 或脚本的数字，用来表示成功、配置问题、凭据来源失败或认证失败等类别。 | 同一个类别可能包含多个底层原因；应同时阅读完整错误文本，并按操作教程验证输出。 |

## HSE2 归档和访问材料

| 名词 | 是什么、用途与大致处理方式 | 需要知道的限制 |
|---|---|---|
| HSE1 / HSE2 | 项目不同代际的加密工作流或归档格式名称。 | 能力和兼容性不同；迁移前保留旧副本。 |
| 归档 / container | 一个文件中保存加密内容及恢复所需结构信息的容器。 | 归档不是备份策略；唯一副本损坏仍会造成数据丢失。 |
| header / footer | 归档前部和末尾用于标识、描述或定位数据的结构信息。 | 手动修改可能让归档无法打开。 |
| manifest | 描述批次或归档中对象及其关系的清单。 | 可能包含名称、路径或数量；要与对应批次配套。 |
| descriptor | v5 中描述一个视图内容结构的记录。 | 不代表隐藏内容或可否认性。 |
| root key | 保护归档内容的核心随机密钥。 | 用户通常不直接输入；丢失所有有效解锁路径会无法恢复。 |
| keyfile | 文件形式保存的密钥或解锁材料；HSE2 可以将它用于创建和解锁归档。 | 按归档的 wrapper 配置提供；单独备份并分开放置，丢失可能无法恢复。 |
| wrapper | 加密保护 root key 的访问封装，不同 wrapper 可对应不同凭据；wrapper id 用于识别某一条记录。 | 可列出、添加、移除或重新包装；修改时程序写入新归档副本。移除前先验证仍可用的恢复凭据。 |
| `access_destroyed` / 永久禁用访问 | HSE2 输出副本中的标记；该副本不再含 wrapper，应用不会按正常流程解锁它。 | 加密主体仍是密文，不是安全擦除。原归档、旧 header backup、快照或其他副本仍可能恢复访问；不得把此操作用于真实数据练习。 |
| header backup | 保存 HSE2 归档头部及主体定位/摘要元数据的材料，可用于特定头部恢复。 | 不含口令或 keyfile，不能修复加密主体损坏；必须与相应主体匹配，并与归档分开放好。 |
| DPAPI | Windows 的用户/设备相关保护机制，可用于保护 keyfile。 | 更换用户或设备可能影响解锁，不是跨设备通用备份。 |
| DPAPI blob | 经 Windows DPAPI 保护的二进制材料；HSE2 `dpapi` provider 会在当前 Windows 范围内解开并用于单文件配置。 | 不能当作可移植 keyfile；保护操作不会删除原始 keyfile。 |
| DPAPI wrapper | 用当前 Windows DPAPI 保护 HSE2 归档的解锁材料。 | 账户、设备或系统变化可能导致无法解锁；重要归档另备并测试口令或 keyfile wrapper。 |
| DPAPI `local_machine` scope | 把 DPAPI blob 保护绑定到创建它的 Windows 计算机，而非单一账户。 | 同机任何账户只要能读取 blob 都可能解密；仅用于信任同机所有账户的场景。见[scope 练习](dpapi-local-machine-practice.md)。 |
| BitLocker To Go | Windows 用于 USB、SD 卡等可移动数据卷的 BitLocker 加密。 | 本项目 GUI 的加密/解锁/上锁代码要求管理员权限；保存 48 位恢复密码。见[入门练习](bitlocker-removable-practice.md)。 |
| BitLocker 恢复密码 | BitLocker 生成的 48 位数字应急凭据，可在恢复流程中解锁卷。 | 持有者可访问盘内数据；应与设备分开保管，丢失后 Microsoft 支持无法重建。 |
| 已用空间加密 | 启用时只加密卷中已被文件系统标记为已用的空间。 | 速度更快，但重用过的旧卷可能残留可恢复的未加密旧数据；不是安全擦除。 |
| 自动解锁 | 将特定电脑/用户配置为自动解锁 BitLocker 数据卷。 | 便利性会减少再次输入设备密码的机会；本 GUI 默认选择禁用。 |

## 配置、校验和恢复

| 名词 | 是什么、用途与大致处理方式 | 需要知道的限制 |
|---|---|---|
| JSON 配置 | 保存输入输出路径、模式和密码来源等任务设置的文本文件。 | 可能暴露路径或明文凭据，分享前检查。 |
| CLI / 命令行 | 在 PowerShell 等终端输入命令来运行程序；每个命令通过参数指定输入、输出和凭据来源。 | 不要把真实口令放入命令行参数或 shell 历史；先确认输入、输出路径。 |
| 生成配置 | 按所选用途和批量密码表模式写出可编辑 JSON 模板。 | 只生成文件，不会执行加密或验证真实输入/口令。 |
| 配置检查 / validate-config | 按加密或解密用途检查 JSON 字段与配置规则。 | 通过不代表输入文件、口令、磁盘空间或加解密任务可用。 |
| schema / 配置规则 | 程序用于判断配置字段名称、类型和组合是否合法的一组规则。 | 通过 schema 检查不是完整运行测试。 |
| compatible / hardened / no-password-tables | 主 GUI 批量任务的三种密码表保存方式：完整保存、少保存一份、不保存密码表。 | 模式不同会影响恢复时要准备的材料；不是 HSE2 v4/v5 的 KDF profile，也不自动保管口令。 |
| password provider | JSON 配置中指定程序运行时从环境变量、隐藏提示、文件、命令、keyfile 或 DPAPI 材料取得密码/解锁材料的设置。 | JSON provider 不含 stdin 类型；DPAPI 可用范围取决于 blob scope；密码文件和环境变量不是保险库。见[CLI 密码来源练习](cli-password-provider-practice.md)。 |
| stdin / 标准输入 | CLI 从管道等输入流读取文本的接口；HSE2 指定命令用 `--password-stdin` 或 `--passwords-stdin` 读取固定数量的口令行。 | 行数和顺序必须按命令；输入内容仍是进程中的明文，也不会自动接入密码保险库。 |
| exit code / 退出码 | 命令结束时返回给 PowerShell 或自动化脚本的数字状态；本项目命令成功时返回 `0`，失败时返回非零值。 | 自动化应立刻检查 `$LASTEXITCODE`；前一步失败就停止，不要把后续输出当成成功结果。 |
| 文件密码 | 保护某个具体文件内容的口令。 | 批次中可能存在多个文件密码，要保管好对应关系。 |
| 单独文件密码 | 在 GUI 多文件配置中用“完整路径=密码”覆盖某个输入源的默认口令。 | 路径必须与加密源一致；配置可能只保存环境变量名，需按执行方式提供密码。 |
| 文件夹内单独加密 | 指定文件夹中的某个相对路径使用单独口令加密。 | 用“文件夹路径|相对路径|密码”指定，并在需要随包恢复时启用内部密码表；路径写错会使指定规则不匹配。 |
| metadata password | 保护批次清单、模板或密码表等辅助材料的口令。 | 不一定等于文件密码；恢复需要与正确材料配套。 |
| password table | 批次功能生成的受保护文件口令映射材料。 | 仍是敏感文件，不要与密文一起公开分享。 |
| validate | 按具体命令定义检查配置、元数据或归档是否符合规则。 | 配置校验不等于执行加密；不同校验入口检查范围不同。 |
| verify | 读取并认证归档活动内容，检查认证数据是否通过。 | 不写明文不代表不暴露元数据；通过不是审计或认证结论。 |
| HSE2 归档 | 独立 HSE2 GUI 创建的加密容器；可用口令或其他已配置的解锁方式打开。 | 保管好解锁因子和归档副本；本练习的 v2 不等同于实验格式 v4/v5。 |
| HSE2 配置式加密密文 | 独立 HSE2 GUI 的“加密配置”工作流生成的单文件密文。 | 可与同扩展名的“创建 HSE2 归档”容器使用不同工具；keyfile 轮换仅支持配置式单文件密文。 |
| 完整校验归档 | 使用解锁因子认证 HSE2 归档内容，不写出恢复文件。 | 只能证明本次所选归档和凭据通过该项校验；不是恢复演练或独立安全审计。 |
| 元数据检查 | 无需解锁内容即可读取归档的可见结构信息。 | 可能暴露版本、大小、数据块数量等信息；不要公开分享原始诊断结果。 |
| inspect | 显示归档可见结构和元数据。 | 可能显示文件名、数量或大小等敏感信息。 |
| preview | 恢复前估算目标、冲突和空间需求。 | 不是恢复成功保证；开始前仍要核对目标。 |
| replace | 用完整的新文件清单替换指定视图，并写出新归档。 | 确认清单包含该视图要保留的所有文件；另一视图应继续可用，需校验并恢复核对。 |
| migrate | 把旧格式内容显式导出为新格式。 | 验证新归档能打开前，不要删除旧归档。 |
| compact | 以归档当前仍活动的内容重写到新容器，丢弃新副本内不再引用的过期记录。 | 原容器和其他副本不变；普通 compact 不安全擦除磁盘、快照或备份上的旧密文。 |
| atomic replace | 文件系统层面用完整新文件替换目标名称，避免出现半写入目标。 | 不等于断电持久性，也不等于安全删除。 |

## v4、v5 与安全边界

| 名词 | 是什么、用途与大致处理方式 | 需要知道的限制 |
|---|---|---|
| v4 / v5 | HSE2 的实验性归档格式版本。 | 按实验格式谨慎使用；先看对应界面警告和路线图限制。 |
| 固定记录容量 / v4 capacity-records | v4 创建时预留的记录槽总数，均分给两个视图；文件内容分块后占用各自槽位。 | 影响每视图可容纳的数据量与归档体积；创建后不能扩容，替换时可复用旧槽位。见[v4 实验练习](v4-practice.md)。 |
| v4 视图 | 由 primary 或 secondary 口令解锁的一套文件清单与数据。 | 两套视图都属于公开的容器结构，不是隐藏卷或可否认性功能。 |
| 双视图 | v5 公开提供两个分别由口令解锁的内容视图。 | 两个视图的存在是公开设计；不隐藏另一个视图。 |
| 备用内容 | 将第二组文件作为可访问的备用数据保存。 | 不承诺可否认性、隐藏卷、抗胁迫或反取证。 |
| credential slot | v5 中保存某个视图凭据封装信息的位置。 | 单视图口令更新只改所选凭据并写出新副本，无法验证另一视图密码是否相同。 |
| 可否认性 | 在特定威胁模型下，无法证明某份隐藏数据存在的性质。 | 本项目 v5 不提供也不承诺这种性质。 |
| 安全删除 | 试图确保删除数据无法从存储介质恢复。 | 普通删除或 compact 不保证 SSD、快照、备份或旧密文已被物理清除。 |

不确定某项操作会读写哪些文件时，先取消操作并从[功能教程地图](README.md)进入对应指南。不要只根据术语推测界面行为。
