# BitLocker To Go：可移动设备安全入门

本练习讲解主 GUI 的“移动存储加密”页如何管理 USB/SD 设备。它会启用 Windows BitLocker To Go，并直接影响所选卷；请先读完风险和恢复密钥部分。项目的自动化测试只模拟命令，不会替你验证真实 USB 设备。本文也不要求现在对真实设备执行加密。

## 先理解这几个词

- **BitLocker To Go**：Windows 对 USB 闪存盘、SD 卡和外接数据盘等可移动数据卷提供的 BitLocker 加密功能。设备移到另一台支持 BitLocker 的 Windows 电脑后，通常可用密码或智能卡解锁。[Microsoft BitLocker FAQ](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/faq)
- **盘符 / 挂载点**：资源管理器中类似 `E:` 的卷标识。本程序仅列出检测到盘符的 USB/SD 分区；同一物理设备可能有多个分区。
- **解锁密码**：日常打开卷时输入的密码。点击“解锁设备”只恢复当前会话的访问，不会关闭加密或删除密码。
- **恢复密码 / 恢复密钥**：忘记解锁密码或 Windows 要求恢复时使用的应急材料。BitLocker 恢复密码是 48 位数字；知道它的人也可解锁并访问卷内数据。[查找 BitLocker 恢复密钥](https://support.microsoft.com/windows/security/encryption/find-your-bitlocker-recovery-key)
- **已用空间加密**：启用时只加密当前已使用的空间，速度较快；曾存有敏感数据的旧卷，其空闲区可能保留可恢复的旧数据。新盘以外的已有数据盘优先完整加密。[Microsoft BitLocker 规划指南](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/planning-guide)
- **自动解锁**：在特定 Windows 电脑和账户下自动恢复访问的便利选项。该 GUI 默认勾选“禁用自动解锁”，也就是拔出后再次插入时仍需手动解锁。

## 开始前：确认目标和恢复办法

1. 备份目标设备上的重要文件，并确认备份可读取。加密不会替代备份。
2. 插入目标 USB/SD 设备，打开本程序主 GUI 的“移动存储加密”页，点“刷新设备”。
3. 在设备列表中逐项核对**盘符、卷标、文件系统、容量、总线类型**。本程序会列出 USB/SD 总线设备；不要只凭盘符判断。若容量、卷标或设备名对不上，停止操作。
4. 确认目标盘里没有打开的文件、资源管理器窗口或正在读写它的程序。加密完成前不要拔出设备。
5. 此项目的 BitLocker 操作代码要求管理员权限；在某些 Windows 策略或管理环境里可用权限不同。若页面提示权限不足，按设备管理员的要求处理，不要尝试绕过策略。
6. 选择一个**位于目标设备以外**的本地目录保存恢复信息。程序会检查目录可写，并拒绝把恢复信息保存在目标盘符所在卷；之后先创建恢复密码保护器、写出 `BitLockerRecovery-盘符-标识.txt`，再启动加密。这遵循 Microsoft 文档中“先添加并保存恢复密码保护器，再启用 BitLocker”的常见流程。[Enable-BitLocker](https://learn.microsoft.com/en-us/powershell/module/bitlocker/enable-bitlocker?view=windowsserver2025-ps) 若启动命令报错，错误消息会指出恢复文件路径；保留该文件并检查卷状态后再决定如何处理。
7. 把恢复文件放在与设备分离的位置，另做至少一份受控备份。不要把恢复文件提交到 Git、发给他人或放回同一只 USB/SD。丢失恢复材料可能导致无法取回数据；Microsoft 支持也不能重建丢失的密钥。[Microsoft 恢复密钥说明](https://support.microsoft.com/windows/security/encryption/find-your-bitlocker-recovery-key)

## 第一次启用加密

此步骤会改变真实设备状态。第一次练习请使用专门的、可擦除的空白测试盘，并确认已备份；不要使用唯一副本或装有重要资料的盘。

1. 选中已确认的设备行。核对下方“目标盘符”与设备表一致。
2. 选择恢复信息保存目录；该目录必须在目标设备之外。
3. 选择加密方式。默认值为 **XTS-AES 256**；不要为兼容性随意更改，除非你明确知道目标 Windows 环境有特殊要求。
4. 输入设备密码，并在确认框再输入一次。使用与 Windows 登录密码不同的强密码，保存在密码管理器中。
5. 默认不要勾选“仅加密已用空间（新盘更快）”。程序默认执行完整卷加密。若启用“仅加密已用空间”，它只覆盖启用时已使用的区域；曾在此卷存放过的已删除敏感文件不因此获得安全擦除。Microsoft 对已有或重用过的卷建议考虑完整加密。
6. 保持“禁用自动解锁，拔出后重新插入仍需手动解锁”勾选。这样其他人接触到这台已登录的电脑时，不会仅因自动解锁设置而省去设备密码这一步。
7. 再次检查盘符、容量、恢复目录和两次密码，然后点击“开始加密”。程序会先将恢复密码保存到所选目录，再请求 Windows 启动加密。在任务结束前不要拔盘、休眠或关闭程序；若 Windows 显示加密仍在进行，等待状态完成后再安全弹出。
8. 成功消息会显示恢复信息文件路径。打开该文件确认它存在，并确认其中的设备盘符与目标设备匹配；不要把 48 位恢复密码粘贴到聊天、工单或公开截图中。关闭文件后将其存入预先准备的安全位置。
9. 点“刷新设备”，核对目标行的加密状态、保护状态、锁定状态和进度。加密百分比可能尚未到 100%；不要因“已启用保护”就推断转换已经完成。

## 解锁、访问和上锁

1. 选中已启用 BitLocker 的目标卷。在“设备密码”中输入日常解锁密码，点击“解锁设备”。成功后密码输入框会清空。
2. 点“打开盘符”即可在资源管理器中访问文件。解锁只恢复当前访问权限，卷仍保持 BitLocker 加密。
3. 保存所有文件，关闭目标盘中的文件、资源管理器窗口以及可能占用该卷的程序。
4. 点击“立即上锁”。本程序调用 `Lock-BitLocker -ForceDismount`；Windows 文档说明此参数会尝试在卷仍被使用时也锁定它。因此先关闭占用者，避免强制卸载打断写入或应用操作。[Lock-BitLocker 文档](https://learn.microsoft.com/en-us/powershell/module/bitlocker/lock-bitlocker?view=windowsserver2025-ps)
5. 点“刷新设备”，确认锁定状态为 `Locked`。正常安全弹出设备后再拔出。重新插入后按需输入密码解锁。

## 出错时怎么处理

- **设备列表为空**：确认设备已插入、有盘符、属于 USB 或 SD 设备，然后刷新。无盘符的分区不会出现在本程序列表里。
- **BitLocker 模块不可用**：本 GUI 无法执行该工作流；不要改用不熟悉的脚本绕过。检查 Windows 版本/管理策略并联系设备管理员。
- **权限不足**：本程序代码会在非管理员上下文阻止加密、解锁和上锁。以管理员方式运行是否合适取决于这台电脑的管理规则；受管设备请先遵从组织策略。
- **密码不匹配或未填写恢复目录**：修正输入后再开始。开始前确认保存目录可写。
- **状态显示转换中**：这代表加密仍在进行，不代表失败。保持供电和连接，刷新状态；不要格式化、初始化或移除该设备。
- **启动加密时报错**：错误消息会给出已保存恢复文件的路径。保留该文件和设备原状，记录错误文本，刷新设备列表确认 BitLocker 状态；在确认转换状态前不要重复启动或格式化设备。
- **恢复文件创建失败**：程序会在启动加密前报告失败。检查目录权限和可用空间后再试；若错误指出恢复保护器已创建，先刷新设备状态，不要盲目重复操作。
- **忘记密码**：先根据恢复密钥 ID 查找对应的 48 位恢复密码。若找不到恢复材料且卷要求恢复，Microsoft 支持不能替你重建密钥。[查找恢复密钥](https://support.microsoft.com/windows/security/encryption/find-your-bitlocker-recovery-key)
- **想取消加密**：本页面没有“解密/关闭 BitLocker”按钮。“立即上锁”只阻断访问，不会关闭加密；不要把上锁当作解密。关闭 BitLocker 会启动解密并将卷恢复为未加密状态，应由你在确认完整备份后通过受支持的 Windows 管理界面操作。

## 完成标准

- 你能从设备属性正确识别目标卷，而不是猜盘符。
- 你能解释解锁、上锁、自动解锁和恢复密码分别做什么。
- 对实际设备练习时，目标卷已完成加密、恢复文件已另存并核对、可以解锁访问、关闭文件后可上锁。

**验证边界：**仓库自动化测试模拟 BitLocker PowerShell 与 GUI 数据，不会启用、解锁或上锁真实设备。本教程的真实设备练习由使用者自行决定并操作；本次推进没有触碰任何实体磁盘。
