# 批量加密与解密：GUI 跟练

- **预计时间：**约 25 分钟
- **适用对象：**已经完成[首次使用练习](first-run.md)的用户
- **需要准备：**主 GUI、两个可删除的样例文本文件、一个新的练习目录
- **练习数据：**虚构内容和两组虚构口令；不要使用真实资料

本练习把两个文件打包为一个加密包，并在包内保存恢复所需的 manifest、template 和加密密码表。解密时使用“快速使用”页签打开 .zip.hse 包。为了让快速入口用同一个口令解开外层包和包内材料，本次练习把主加密密码与密码表/清单密码设为相同值；这只为简化跟练，不应推导成适用于所有工作的密码策略。

## 1. 准备文件和目录

1. 创建一个临时目录 HSE-批量练习，并在其中创建 输入、输出 和 恢复 三个子目录。
2. 在 输入 中创建 alpha.txt 和 beta.txt，分别写入不同的虚构内容并保存。
3. 选一个虚构练习口令，本次主加密密码和密码表/清单密码使用同一值。它不能是你的真实账户密码。

## 2. 设置批量加密

1. 打开 high-security-encryptor-gui.exe，进入“文件加密”页签，再进入“多文件配置”。
2. 点击“添加文件”，同时选择 输入\alpha.txt 和 输入\beta.txt。也可以在文件列表中每行填写一个完整路径。
3. 在“主加密密码”和“密码表/清单密码”都填写同一个练习口令。
4. 将“输出目录”设为 HSE-批量练习\输出，将“密码表保存方式”设为“简单兼容：保存完整密码表”。
5. 勾选“文件夹内单独加密时输出内部密码表”。该选项让程序把恢复包内加密文件所需的口令映射一起保存在加密包内。
6. 在“配置保存到”选择 HSE-批量练习\encrypt.json。该配置会保存密码来源的环境变量名称，不会把刚输入的口令写成 JSON 明文。
7. 本练习不填写“单独文件密码”和“文件夹内单独加密”区域。点击“生成并开始加密”，等待运行结果。

**预期结果：**界面日志显示加密配置位置、打包输出位置以及任务结果。因为输入了两个文件，程序会将它们打成一个 .zip.hse 文件。记录日志显示的实际路径。恢复所需的内部 manifest、template 和加密密码表保存在包内。

## 3. 用快速使用打开批量包

1. 进入“快速使用”页签，在“我要”选择“解密”，点击“选择文件”并选择日志里记录的 .zip.hse。
2. 输入刚才使用的同一个练习口令，点击“一键开始”。
3. 查看日志报告的恢复目录；包会解密到一个新目录，里面的两个 .txt 文件会自动恢复为普通文件。

## 4. 核对恢复结果

打开恢复目录中的 alpha.txt 和 beta.txt，分别与 输入 文件夹中的原件逐字核对。内容一致后，本次批量练习完成。可以删除整个 HSE-批量练习 临时目录；删除前确认里面没有需要保留的文件。

本教程演练的是“多文件配置生成一个加密包，再用快速使用解密该包”。“文件解密”里的“多文件解密配置”用于恢复一批独立 .hse 文件及其批次辅助文件；它的输入不是这里生成的单个包，本教程不把两种路径混为一谈。

## 常见问题

| 现象 | 原因或处理 |
|---|---|
| 找不到 .zip.hse | 以加密日志中的实际输出路径为准；不要只凭文件名猜目录。 |
| 解密失败 | 检查输入的是本次创建的 .zip.hse 和同一个练习口令；保留原文件，不要覆盖未知输出。 |
| 恢复目录已有内容 | 选择新的空位置再运行，避免和已有资料混淆。 |
| 关闭 GUI 后配置无法独立运行 | GUI 仅为“生成并开始”这一次运行临时设置环境变量。后续独立运行需按说明自行设置配置引用的环境变量。 |

## 这几个文件分别做什么

- **.zip.hse 加密包：**保存打包后的加密文件内容。
- **manifest：**列出包内预期的加密对象并绑定批次身份。
- **template：**记录包内恢复所需的口令来源和结构信息。
- **加密密码表：**在本兼容模式下保存受密码保护的包内文件口令映射。
- **metadata password：**界面中的“密码表/清单密码”；用于读取包内辅助材料。在本练习中为了使用单口令快速恢复，它与主加密密码相同。

这些材料配套才可恢复。不要把明文口令、密码文件和加密包一起公开分享。更高级的密码来源和安全模式见[图形界面使用说明](../beginner_gui_usage.md)。
