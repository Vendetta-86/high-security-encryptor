# 单独文件口令与文件夹内口令：GUI 跟练

- **预计时间：**约 20 分钟
- **适用对象：**已完成[批量加密与解密练习](batch-practice.md)的用户
- **需要准备：**主 GUI、两个可删除的练习文本文件、一个临时练习目录
- **练习数据：**虚构文本和三组虚构口令；不要使用真实资料

本练习把一个普通文件和一个文件夹打成一个 `.zip.hse` 加密包。普通文件使用单独口令；文件夹中的一个指定文件再使用文件夹内口令。恢复时用包的 metadata password 打开外层包，程序根据内部恢复材料还原各文件。v1.0 批次功能在此流程中不承诺可否认性。

## 1. 准备临时文件

在临时目录 `HSE-分项口令练习` 中建立以下结构：

```text
HSE-分项口令练习/
├─ 输入/
│  ├─ alpha.txt
│  └─ docs/
│     ├─ visible.txt
│     └─ private/
│        └─ secret.txt
├─ 输出/
└─ 恢复/
```

给三个文本文件分别写入不同的虚构内容。选择三组互不相同的练习口令，分别代表“包口令”“alpha 文件口令”和“文件夹内 secret 文件口令”。这三组都不能是你的真实密码。

## 2. 设置多文件加密

1. 打开主 GUI，进入“文件加密”→“多文件配置”。
2. 在“加密文件/文件夹，每行一个”中添加 `输入\alpha.txt` 和 `输入\docs` 文件夹。确认添加的是文件夹本身，不要分别添加其两个内部文件。
3. “主加密密码”填写第一组练习口令。“密码表/清单密码”也填写同一组，以便之后用快速使用页签的同一口令打开外层包。
4. “输出目录”设为 `HSE-分项口令练习\输出`；“密码表保存方式”选择“简单兼容：保存完整密码表”。
5. 在“单独文件密码”文本框输入一行：

   ```text
   alpha.txt 的完整路径=第二组练习口令
   ```

   等号左侧必须与第 2 步添加的源文件完整路径一致。没有列出的输入对象使用“主加密密码”。

6. 在“文件夹内单独加密”文本框输入一行：

   ```text
   docs 文件夹的完整路径|private/secret.txt|第三组练习口令
   ```

   两个竖线分隔文件夹路径、相对路径和该文件的口令。相对路径从 `docs` 文件夹内部开始，使用 `/`；必须与真实文件位置一致。

7. 勾选“文件夹内单独加密时输出内部密码表”。这会把恢复文件夹内单独加密文件所需的口令映射放入加密包配套的保护材料中。不要勾选其他“输出加密密码表”选项，本练习使用默认设置。
8. “多文件加密包保存到”可留空使用默认位置，也可以指定 `输出\practice.zip.hse`。配置保存位置设为练习目录中的 `encrypt.json`。
9. 点击“生成并开始加密”。本 GUI 会为本次运行临时提供你刚输入的口令；JSON 保存的是环境变量引用。以后单独重新运行该 JSON 时，需要另行提供这些环境变量，详见[密码来源说明](../beginner_gui_usage.md)。

**预期结果：**日志显示配置文件和一个 `.zip.hse` 加密包。保留输入原件、加密包和三组练习口令，先不要清理练习目录。

## 3. 用快速使用恢复加密包

1. 切换到“快速使用”，选择“解密”，打开刚才生成的 `.zip.hse`。
2. 输入第一组“包口令”，点击“一键开始”。本次练习的包口令和 metadata password 相同。
3. 从运行日志读取实际恢复目录；程序会创建新目录，不覆盖已有文件。

**预期结果：**恢复目录中包含三个文件。由于包中可能有多个源对象，恢复路径会带编号前缀，例如 `001_alpha.txt`、`002_docs\visible.txt`、`002_docs\private\secret.txt`。以实际日志和目录树为准，不要因前缀与原路径不同就把内容误认为丢失。

## 4. 核对三份内容

分别打开恢复目录里的 `alpha.txt`、`docs\visible.txt` 和 `docs\private\secret.txt`（按实际前缀定位），逐字与输入原件比较。三份内容一致后，本练习完成。手工比对只核对本次样例文字，不等同于独立完整性审计。

## 口令分别保护什么

| 输入位置 | 此处口令用途 | 本练习示例 |
|---|---|---|
| 主加密密码 | 供未单独指定口令的输入对象使用 | `docs` 文件夹的外层内容 |
| 单独文件密码 | 覆盖某个 `sources` 路径的默认口令 | `alpha.txt` |
| 文件夹内单独加密 | 覆盖指定文件夹中的一个相对路径 | `docs/private/secret.txt` |
| 密码表/清单密码 | 保护批次恢复所需的辅助材料；本次也作为 `.zip.hse` 的外层密码 | 与主加密密码相同 |

这几种口令不是互相替代关系。`source` 路径与覆盖行不匹配时，程序不会把覆盖口令应用到你预期的对象；文件夹内路径写错时，目标文件不会按指定规则单独加密。运行前复核完整路径和相对路径；恢复材料、口令或原件不要分开放错批次。

## 常见错误

| 现象 | 检查方式 |
|---|---|
| GUI 提示密码行格式错误 | 单独文件用 `完整路径=密码`；文件夹内单独加密用 `文件夹路径|相对路径|密码`，每行一项。 |
| 输出包没有生成 | 查看日志中的完整错误，确认输入路径存在、输出目录可写且有足够空间。保留原件，不要用不确定的文件覆盖输出。 |
| alpha 用错口令或恢复失败 | 检查单独文件密码左侧路径是否与添加的源文件完全一致，确认口令表/清单口令对应本次批次。 |
| secret 文件似乎没有单独加密 | 对照 `docs` 文件夹内部的相对路径，确认启用了“文件夹内单独加密时输出内部密码表”。 |
| 快速使用无法打开包 | 确认选中的是本次输出的 `.zip.hse`，并使用第一组包口令；它不是 alpha 或 secret 的单独口令。 |

不要在真实文件上试错口令映射。先用新的临时样例修正并重新生成批次。练习结束后，确认不再需要输出和恢复目录中的文件，再自行删除整个临时目录。
