# 新手错误恢复：先停下来，再定位

本指南适用于主 GUI、独立 HSE2 GUI 和 CLI。它帮助你判断下一步是否安全，不承诺每种故障都能自动恢复。练习只用临时目录和虚构配置；遇到真实资料时，先保留源文件、密文、keyfile、DPAPI blob、备份和错误日志。

## 1. 出错后的共同步骤

1. **先停止重复操作。** 不要连续重试覆盖、替换、wrapper 移除、访问禁用、BitLocker 或恢复操作。
2. **保留所有材料。** 不要删除输入、归档、keyfile、恢复文件或目标目录；失败时不要假设源文件或输出一定完整。
3. **记录上下文。** 记下正在使用的程序入口和命令/GUI 页签、输入与输出路径、操作时间、显示的完整错误文本和退出码。先遮盖口令、keyfile 内容、恢复密钥和个人路径再分享日志。
4. **确认是否成功。** CLI 的退出码 `0` 仅表示命令报告成功；再按当前操作检查输出文件/目录是否存在，并使用该格式对应的校验或教程核对内容。GUI 同样要查看日志中的结果和输出位置。
5. **修正一个原因后再试。** 先复制练习材料或另选一个全新输出路径；不要在唯一原件上试错。

## 2. 先找到完整错误

### 主 GUI“快速使用”

错误弹窗显示失败信息；主窗口日志还会记录异常和通用建议。先读完整日志，不要只凭弹窗猜测口令或文件是否损坏。

### 主 GUI 的配置和批量页

失败时弹窗显示状态码；主窗口日志记录标准输出、错误文本和退出码。向他人求助时，分享脱敏后的完整错误文本和退出码，不要只截取弹窗。

### 独立 HSE2 GUI

在运行日志里查看命令结果、错误文本和退出码。先确认当前动作、归档路径、解锁方式和所选输出目录。

### CLI

查看命令输出和 PowerShell 的 `$LASTEXITCODE`。默认错误通常是一行简短说明，不含 Python traceback。`--debug` 或环境变量 `HSE_DEBUG=1` 会显示 traceback，主要用于开发诊断；分享前先检查并脱敏。

## 3. 常见类别与安全处理

CLI 的错误码由程序分类。GUI 的配置/批量任务也会在日志中显示对应命令的退出码。

| CLI 退出码 | 类别 | 先检查什么 | 安全的下一步 |
|---:|---|---|---|
| `0` | 命令报告成功 | 日志中的输出路径、实际文件/目录和本任务要求的后续校验 | 按对应教程验证；不要把退出码单独当作内容已正确恢复的证明。 |
| `1` | 运行时错误 | 完整错误文本；输入/输出路径是否可访问，目标是否被其他程序占用 | 保留所有文件；修正明确的路径或占用问题后，换新输出位置重试。无法判断时停止并提供脱敏日志。 |
| `2` | 配置检查发现问题 | 报告中的 `error` / `warning`、问题代码和过滤条件 | 按报告修配置后重新检查。仅有 warning 时是否返回 `2` 取决于 `--warnings-as-errors`；不要把 warning 当成加密任务已执行。 |
| `3` | 配置或输入格式错误 | 配置文件是否存在、JSON 是否完整、字段类型和路径是否符合提示 | 只修配置副本；重新运行 `validate-config`，确认检查结果后再执行任务。 |
| `4` | 密码来源错误 | provider 类型、环境变量名称、密码文件/keyfile 路径及文件读取权限 | 不要把口令贴进日志或命令行。确认秘密来源在当前运行环境可读取，再先做只读配置检查或小样例操作。 |
| `5` | 完整性或认证失败 | 是否选错口令、keyfile、DPAPI 用户/设备范围，或归档可能损坏 | 立即停止写入、恢复、替换和重包；保留源归档与所有备份。确认凭据来源后，只在副本上按对应校验教程检查。 |
| `6` | 暴力尝试保护阻止操作 | 日志中的保护提示和剩余等待秒数 | 停止继续尝试，不要用脚本反复调用；保留材料并遵循日志给出的等待时间，再考虑一次人工重试。 |

退出码是 CLI 的稳定分类，不保证每个底层错误都能被精确归到单独原因。尤其 `1` 可能涵盖多种未预期运行时异常；要以本次完整错误文本为准。

## 4. 一个安全的故障定位练习

这个练习故意给配置检查一个不存在的配置文件。它只读地报告错误，不创建或覆盖加密输出。

```powershell
$HSE = "high-security-encryptor"
$Practice = Join-Path $env:TEMP ("HSE-Error-Practice-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $Practice | Out-Null
$MissingConfig = Join-Path $Practice "does-not-exist.json"
& $HSE validate-config --kind encrypt --config $MissingConfig
$ObservedExitCode = $LASTEXITCODE
Write-Output "观察到的退出码：$ObservedExitCode"
if ($ObservedExitCode -ne 3) { throw "预期缺失配置应返回退出码 3；请保留输出并停止。" }
Write-Output "PASS：已定位为配置/输入问题；没有执行加密任务。"
```

若使用 Windows ZIP，把 `$HSE` 设为解压目录中 `high-security-encryptor.exe` 的完整路径。预期错误文本指出配置文件不存在，退出码为 `3`，且没有 traceback。看到其他结果时停止，保留输出并核对 `$HSE` 是否指向本项目程序；不要从网络下载另一个同名程序替代。

## 5. 修复前的检查清单

- 路径是否指向预期的文件、归档、keyfile 或目录？文件名和扩展名是否完整？
- 当前 Windows 用户是否能读取输入和凭据文件，并能写入所选输出位置？
- 是否把 GUI 不支持的 `prompt` provider 用在 GUI 批量任务中？GUI 会明确拒绝这种输入方式；改选教程支持的来源，不要把真实口令写入配置。
- 配置验证报告的状态、问题代码和 warning 是否已逐项看过？报告摘要不会替代输出文件中的完整报告。
- 错误是否涉及凭据不匹配、认证失败、恢复、替换或访问禁用？若是，停止写入操作，只在副本上进一步检查。

## 6. 什么时候不要自行重试

遇到认证/完整性失败、输出被部分创建、恢复内容与预览不符、header backup 与归档不匹配、BitLocker 设备或恢复密钥不确定，或任何可能覆盖/替换/永久禁用访问的提示时，先停止。保留原件和全部相关文件，提供脱敏后的完整日志、退出码、程序版本和你刚执行的动作。不要上传口令、keyfile、DPAPI blob、恢复密钥或真实敏感资料。

每个格式和操作还有自己的限制；本指南不能取代对应的[单文件练习](first-run.md)、[HSE2 归档练习](hse2-archive-practice.md)、[CLI 密码来源练习](cli-password-provider-practice.md)或[BitLocker 练习](bitlocker-removable-practice.md)。
