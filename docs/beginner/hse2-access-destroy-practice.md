# HSE2 GUI：在练习副本上永久禁用访问

本练习演示“永久禁用 HSE2 访问”：程序把一个新归档副本写到单独路径，删除该副本中的全部 wrapper，并标记 `access_destroyed`。它不会改写输入归档，也不会擦除加密主体。

> **只可使用前面练习生成的临时归档和虚构 keyfile。严禁对真实数据、唯一归档或仍需恢复的文件执行本操作。** 练习输出会失去正常解锁路径。原档、header backup、系统快照或其他备份若仍保留访问材料，仍可能恢复访问；本功能不是安全擦除，也不会清除这些副本。

## 你需要准备

先完成 [HSE2 keyfile GUI 练习](hse2-keyfile-practice.md)，确认临时目录中有 `practice.hse2` 和 `practice.key`，并能用该 keyfile 成功打开原归档。再新建空文件夹 `永久禁用练习输出`。本练习不得覆盖 `practice.hse2`。

开始前，先确认：

- 输入是临时练习归档 `practice.hse2`，不是任何真实文件。
- 输出使用从未存在过的新路径 `永久禁用练习输出\practice-access-disabled.hse2`。
- 原归档和 `practice.key` 仍在原位置；不要删除、移动或覆盖它们。
- 若该练习目录里有 header backup，也要保留并记住它可能保存可恢复的旧头部信息。

## 操作步骤

1. 打开独立 HSE2 图形界面，在操作列表中选择 **永久禁用 HSE2 访问**。
2. 输入文件选择 `practice.hse2`。
3. 输出文件填写 `永久禁用练习输出\practice-access-disabled.hse2`。确保输入和输出不是同一个文件，且未启用覆盖。
4. 本练习使用 v2 归档，因此把 `keyfile` 栏留空。v2 的此操作不会校验 keyfile；如果使用 v3 归档，则必须提供现有访问因子，程序才会认证新头部。先前已验证 `practice.hse2` 可用，是为了确认操作对象正确，不代表 v2 的禁用操作本身会验证该 keyfile。
5. 在“永久禁用访问确认短语”栏，逐字输入界面显示的短语：

   `I UNDERSTAND THIS WILL MAKE THE DATA PERMANENTLY UNRECOVERABLE`

6. 再核对一次输入文件、全新的输出路径和确认短语，然后运行。确认对话框会提醒：输出副本将移除全部 wrapper，并无法通过正常 HSE2 流程解锁。

确认短语是高风险操作的额外确认，不会让操作可逆，也不代表程序擦除了密文主体。不要因为这次是练习，就把同样操作用于真实归档。

## 检查结果

1. 在 GUI 中选择“列出 HSE2 wrapper”，检查 `practice-access-disabled.hse2`：应显示 `access_destroyed: true`、wrapper 数量为 `0`。
2. 尝试打开该练习输出副本：程序应拒绝解锁；不应产生恢复出的明文文件。
3. 再对原始 `practice.hse2` 执行完整校验或打开：它仍应能用 `practice.key` 正常工作，恢复内容应与原练习样例逐字节一致。
4. 将这次输出理解为“该副本的 HSE2 访问元数据已禁用”。不要把它当作覆盖原档、擦除磁盘、销毁所有备份或证明所有副本均不可恢复。

如果输出路径、输入路径或选中的归档不是上述临时练习文件，取消操作，回到练习目录重新确认。
