## 3. 新手上手差距

1. 当前已有两个良好入口——主 GUI 快速使用和 HSE2 三步入门向导——但它们只覆盖基础任务，没有串起全部功能。
2. 现有指南按模块散落在 README、`beginner_gui_usage.md`、HSE2 CLI/config/provider/format/threat-model 文档中。用户需要先知道去哪里找，才能知道应该搜什么。
3. 术语缺少面向新手的统一索引。至少需覆盖：HSE1/HSE2、容器/归档、wrapper、keyfile、KDF、DPAPI、密码表、manifest/descriptor/record、alternate view/备用视图、compact、迁移、header backup/body offset、原子替换/fsync。
4. GUI 中虽有安全警告，但许多字段仍直接使用专业词（如 wrapper id、Payload chunk、KDF profile、DPAPI scope、compact）。没有与当前操作上下文关联的解释入口。
5. CLI 与 GUI 的功能分布不同：一些 HSE2 操作只有 CLI；GUI 多处只是把字段转换为命令计划。教程必须标明当前入口和对应命令，不应暗示两个界面具备完全相同的功能。
6. 需要将“是什么、用途、基本工作原理、操作步骤、前置条件、预期结果、失败恢复、限制/风险”作为每个教程/术语条目的统一模板。

## 4. 后续阶段与痛点/验收的对应关系

| 路线图阶段 | 基线发现的痛点 | 验收时应证明 |
|---|---|---|
| 1 — v5 检查与恢复预览 | 现有独立校验入口限定 v2/v3；用户无法从该入口对 v5 活动视图执行完整、无明文输出的校验，也缺少统一恢复前摘要。v5 当前 descriptor 没有明文摘要字段 | 仅凭所选视图凭据，验证 descriptor 和所有活动记录，并核对 manifest 声明的文件/chunk 长度；不保存/输出明文，也不宣称比对归档内明文摘要；恢复前显示输出条目、总量、冲突与目标空间；错误路径不留下正式输出 |
| 2 — 单视图口令更新 | v5 已能更新一视图内容，但当前用户入口没有清晰的“只改本视图口令”流程 | 不需要另一视图口令；另一视图和 payload 不变；新输出独立；错误口令/中断/写入失败保留源文件和目标安全边界 |
| 3 — 零基础教程/术语指南 | 教程和术语分散，入门向导只覆盖基础三步 | 功能目录覆盖全部实际用户入口；每项链接到可跟做教程或说明不适用原因；新手无需预学密码学/命令行、无需猜参数或查外部资料即可完成练习并理解结果/恢复方法 |
| 4 — GUI 路径一致性 | GUI/CLI 功能分布不一致；v5 GUI 单文件映射限制和实验性措辞可能令新手迷失 | 只基于阶段 0/3 证据选择 GUI 改动；教程和界面中的能力声明一致，安全相关选择有上下文说明 |
| 5 — 本地稳定性与发布 | 现有 v0.8.0 有测试和 Windows ZIP 证据，但 3.0 新增流程尚无验收记录 | 新流程、历史格式回归、全量本地测试和 Windows ZIP 门禁证据齐全；教程与发布包一致；未过门槛则维持实验性 |

阶段 2 是新提议，是否实施以实现前的格式/credential-slot 设计和阶段 0 的用途确认作为门槛；不得通过未认证 header 修改访问因子。路线图 3.0 的教程需求来自用户明确提出，作为确定范围处理。

## 5. 阶段 0 结论

- 当前没有可用开放 issue 或历史用户反馈样本来对需求排序；后续 UI 需求优先从现有界面可走通性和已知限制中筛选，不凭空扩展产品范围。
- 阶段 3 是一项确定需求：建立“功能清单 → 术语索引 → 分步教程 → 界面内上下文入口”的完整新手路径，并按安全敏感程度覆盖实际功能。
- 阶段 1 的 v5 校验、阶段 2 的单视图口令更新均不是现有独立用户入口可完成的能力；实施前仍须先检查是否已有内部 workflow 复用。
- 全量回归现已在本轮实际重跑，结果与 v0.8.0 release notes 中的记录一致：763 passed、6 skipped。
- 本轮只完成基线盘点和测试；没有更改程序行为，也没有声称完成格式认证、外部互操作或跨平台验收。
