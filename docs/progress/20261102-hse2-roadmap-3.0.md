# HSE2 Roadmap 3.0

**状态：阶段 0、阶段 1、阶段 2 已完成；阶段 3 进行中**
**基线日期：2026-11-02**  
**承接：路线图 2.0 已完成；v0.8.0 已发布**

本文中的 3.0 指路线图版本，不代表产品版本承诺。3.0 的目标是让已发布的 v5 备用内容容器更容易检查、维护和恢复，并以明确的本地验证门槛逐步决定其稳定性与默认格式；不以增加格式数量为目标。

## 1. 当前基线

- 当前产品版本为 v0.8.0，Windows x64 ZIP 已发布。2026-11-03 本地全量回归为 780 项通过、6 项跳过；尚未据此生成新发布包。
- HSE2 v2/v3/v4 保持可读写；v5 已支持流式创建、打开、单视图替换、单视图口令更新、双口令 compact、v4→v5 显式导出、完整校验和恢复预览，并接入 CLI 与实验 GUI。
- v5 是公开的双视图备用内容格式。格式和界面不得暗示隐藏卷、可否认性、抗胁迫、反取证或安全删除。
- v5 有界 manifest、单视图更新保留另一视图、失败时保留源容器等本地测试覆盖。`os.replace` 的原子可见性不等于断电持久性；当前不承诺断电恢复或底层介质上的安全删除。
- v5 创建仍为显式选择；现有默认格式不因 3.0 自动改变。待有真实使用反馈并完成迁移影响评估后，再作默认格式决策。
- 截至本计划核对时，GitHub 仓库没有开放 issue；路线图 3.0 不是已收集到的用户需求清单，阶段 0 负责建立实际需求基线。

## 2. 3.0 目标

1. 用户能在不解密落盘的情况下判断 v5 容器的结构和活动内容是否通过完整性验证，并在恢复前看到目标冲突与空间需求。
2. 用户能在保留原档案和另一视图的前提下更新单个视图的口令；操作失败不得损坏原容器。
3. GUI 与 CLI 对上述常用 v5 工作流提供一致、可理解的功能和风险说明。
4. 大幅降低无基础新手使用门槛：提供覆盖所有用户可见功能的分步教程和术语说明，使新手能从首次启动开始，按指导完成各功能的安全操作。
5. 为 v5 建立可重复的本地兼容性、故障恢复、打包验收门槛，并以实测证据而非认证标签决定是否提升格式状态。
6. 继续读取 v2/v3/v4；所有不兼容的容器布局变化都必须另行设计格式版本和迁移方案。3.0 本身不引入 v6。

## 4. 关键不变量与决策门

- 对任何创建、替换、口令更新、compact 和迁移操作：输入档案保持不变，目标只在完整成功后发布；错误与取消路径不留下可被误认作成品的部分输出。
- 只读检查可暴露活动视图中的文件名和元数据给本机调用者；它不隐藏文件大小、容器增长、历史密文或操作痕迹。
- 口令更新必须使用现有 credential slot 的认证路径，不允许通过未认证 header 写入、自动回退或宽松模式绕开验证。
- v2/v3/v4 的读取兼容是回归门槛；不修改旧格式的 wire layout，不自动转换用户档案。
- v5 是否成为默认创建格式是单独决策：需要真实使用反馈、兼容性/迁移说明和发布前的本地验收证据。3.0 不预先批准切换。
- 新手教程的覆盖范围以实际用户可见功能清单为准；不把内部开发接口伪装成面向新手的产品功能。遇到无法安全简化的操作，教程必须解释前置知识、失败后果和安全边界。
- 若阶段 0 没有支持 GUI 扩展或口令更新的实际需求，阶段 4 或阶段 2 可缩减/延后；不得为填满路线图而实现功能。

## 5. 不纳入 3.0

- 真正可否认性、隐藏卷、诱饵/胁迫口令、反取证、自动销毁真实数据或系统痕迹保护。
- 第三方认证、独立实现互操作或外部审核作为阶段、发布或完成门槛。项目按自用项目执行本地设计审阅、自动化测试和边界披露。
- v6 或其他新容器格式；v5 默认格式切换；静默迁移、原位格式升级或删除旧格式支持。
- 云同步、账户系统、远程密钥托管、移动端、内核/虚拟磁盘驱动。
- SSD、快照、日志或备份中的明文/旧密文安全擦除承诺；断电持久性承诺。
- 无明确需求的递归批量重包、自动 keyfile 生成/轮换或跨平台 GUI 发布。
