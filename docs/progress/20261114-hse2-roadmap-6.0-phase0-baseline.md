## 已确认的主要差距

1. **入口分散：**主 GUI、独立 HSE2 GUI、嵌入式 HSE2 页和专题 CLI 各有自己的发现路径；新手先要判断应从哪个入口开始。
2. **向导覆盖不对称：**HSE2 快速开始能演示固定三步，但不是面向所有常见目标的通用任务向导；许多解释位于独立教程中。
3. **长任务体验分层：**源码中能看到线程与 UI 回调，但当前实现分布于各 GUI 操作路径；此次盘点没有发现一个统一的跨功能作业状态/结果契约。阶段 1/3 仍需结合完整调用图确认可复用部分。
4. **操作前后信息不一致：**底层已有校验、预览和恢复计划能力，但不同入口的呈现与错误说明需要被统一审查；不能因此重复实现底层校验。
5. **性能证据按格式分散：**v3 有界内存已有历史基准，不能据此推断 v2/v4/v5 或每种操作都具有相同内存特性；6.0 应先建立格式/操作矩阵再设优化目标。

## 核心任务合同与指标

首批代表任务：

1. 加密单文件/文件夹并定位输出。
2. 打开并恢复既有归档，理解所需密码来源和覆盖选项。
3. 只读校验或预览恢复计划，不写出明文。
4. 查看失败结果并安全重试，不重复覆盖成功项。
5. 识别 HSE2 v4/v5 实验功能及其能力边界。

6.0 的体验目标（阶段 1–4 的验收指标）：

- 上述每项任务从统一入口开始，不需要用户先猜产品入口或内部格式名；一个任务最多经过两个明确的导航选择到达工作界面。
- 执行前能看见输入、输出/目标、凭据来源、格式或实验状态，以及会覆盖/写出的内容；不以模糊默认值执行破坏性操作。
- 每个长任务都有可辨认的运行/成功/部分成功/失败/取消状态。百分比只有在底层能提供可信计数时显示。
- 代表性新手走查中，用户可复述“操作了什么、文件写到哪里、凭据从哪里来、失败后怎么处理”；遇到含糊提示先修正文案/界面再宣布阶段通过。
- 任何 GUI 作业状态或历史均不得包含密码、恢复口令、keyfile 内容或明文内容；默认不保存完整明文路径历史，也不跨重启自动续跑。
- v2/v3/v4/v5 读写行为按既有契约保持；v5 仍实验性，默认新建仍为 v2，6.0 不隐式改变格式。

## 风险边界决策

- 取消仅在各工作流定义的安全点生效；不得通过强杀线程伪装回滚。
- 逐文件 staging/提交继续作为已知恢复保证；若后续提出整目录原子提交，需单独设计 Windows 目录改名、目标已存在、磁盘满和断电语义，不能顺带实现。
- 作业队列首版不持久化敏感参数、不自动重试、不自动恢复上次运行。
- BitLocker 仍需设备状态门禁与明确确认；当前阶段 0 不触发任何真实设备写操作。
- 不把第三方审查、用户遥测或外部认证作为完成条件；以本机测试、打包件和自用走查证据验收。
