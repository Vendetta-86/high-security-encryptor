# HSE2 Roadmap 3.0 Phase 2 Implementation Record

**状态：完成**  
**日期：2026-11-03**

## 交付内容

- 新增 `hse2 v5-password-update --input <SOURCE> --output <NEW_OUTPUT>`。CLI 隐藏提示当前口令、新口令和确认；自动化可用 `--passwords-stdin` 提供三行输入。
- 在 GUI 增加“实验性 HSE2 v5 单视图更换口令”入口。用户只需当前视图口令、新口令及确认；执行前的确认框解释源档案和新输出的口令差异、目标覆盖行为及另一视图的口令约束。
- 新凭据使用原 credential slot 的 Argon2id profile 和随机 salt/nonce，重新加密相同的视图 root key。输出容器保留 source archive id、另一 credential slot、descriptors、encrypted records 和 footer。
- 更新 CLI 工作流文档，说明完整副本所需空间、`--force`、备份/旧副本的处理方式，以及何时旧密码仍有效。

## 安全与失败边界

- 必须使用当前有效口令解锁对应 credential slot；错误口令不能产生输出。
- 输入与输出路径必须不同。源文件保持不变；写入先进入临时目标，完整复制后才原子替换目标路径。
- 已知可用空间不足时在临时文件创建前失败。注入的复制/写入失败、最终 `os.replace` 失败会清理临时文件并保留源文件。
- 只能根据所选视图的当前口令进行更新。新口令必须和另一视图口令不同，但系统无法在不读取另一口令的情况下验证用户选的口令是否重复；CLI、GUI 和文档均披露此约束。
- 原档案和此前备份/副本均保留旧 credential slot 与旧口令；更新不会修改或清理它们。
