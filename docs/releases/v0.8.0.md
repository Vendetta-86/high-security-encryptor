# v0.8.0

This release adds the first compact HSE2 v5 container implementation while retaining v2, v3, and v4 compatibility. HSE2 v5 is an alternate-content format with two separately authenticated views. It does not provide plausible deniability, hidden volumes, coercion resistance, anti-forensics, or host trace protection.

## Highlights

- HSE2 v5 uses variable-length authenticated descriptors and on-demand encrypted records, avoiding v4's fixed 128 MiB descriptor reservation for small archives.
- Added streaming create, restore, single-view replacement, two-password compact, and explicit v4-to-v5 export workflows.
- Added CLI and experimental GUI support for v5. Replacement and migration write a new output and preserve the source archive.
- Improved GUI onboarding with capacity estimates, destination free-space checks, beginner help, and included examples.
- Preserved existing v2/v3/v4 readers and writers. The v5 writer is explicit; this release does not silently change the default format.

## Validation

- Full local suite: 763 passed, 6 skipped (Windows 11 x64, Python 3.13.15).
- `pre-commit run --all-files`, `pip-audit`, `compileall`, and `git diff --check` passed locally; pip-audit found no known vulnerabilities.
- Ten isolated process samples per operation across seven v5 input scenarios are recorded in [`the local baseline`](../progress/20261102-hse2-v5-baseline-10run.md). These measurements characterize one machine and are not portable performance guarantees.
- Exact-tag Windows EXE workflow gates publication: it builds ten executables, runs CLI/GUI smoke checks and package tests, packages the ZIP, verifies the downloaded ZIP, and computes its SHA-256 digest.

## Durability and security limits

- Same-directory staging plus `os.replace` provides atomic visibility where supported. `HSE_FSYNC=1` requests a file-data flush before replacement; directory-entry and storage-device power-loss persistence are not guaranteed.
- The two views are not hidden. The format does not claim plausible deniability, coercion safety, or forensic resistance.
- Replacement preserves the original archive. Compact and v4-to-v5 export require both view passwords and write a separate output.
- The project does not promise secure erasure of old data from SSDs, snapshots, journals, backups, or operating-system caches.
