# v0.6.0-alpha.9

**Status: release candidate preparation; not published.**

This candidate follows alpha.8 and includes the HSE2 standalone GUI input-validation fix discovered while exercising permanent access-disable safeguards.

## Highlights

- Invalid HSE2 action input, including an incorrect access-disable confirmation phrase, now produces a visible validation dialog instead of escaping the GUI callback.
- Password fields are cleared after validation errors; invalid plans do not reach the command runner or create output archives.
- Retains HSE2 v2/v3 compatibility and the previously documented Windows restore-path hardening.

## Validation status

- Windows 11 x64 / Python 3.13.15: full suite passed (681 tests, 4 skipped); `pre-commit`, `pip-audit`, and `compileall` passed.
- Packaged HSE2 GUI negative-path test displayed `永久禁用访问确认短语不匹配。` and created no output. The original disposable archive remained unchanged.
- Packaged HSE2 GUI positive-path test wrote a separate disposable archive; metadata inspection confirmed `access_destroyed=true`, `wrapper_count=0`, and zero wrappers, while the original archive retained its password wrapper.
- GitHub CI run [41206186803](https://github.com/Vendetta-86/high-security-encryptor/actions/runs/41206186803) passed on Windows Python 3.11, 3.12, and 3.13.
- The alpha.8 tag artifact predates the GUI validation fix and is not the artifact for this candidate. Exact-tag Windows packaging and artifact inspection for alpha.9 remain release gates.

HSE2 v3 remains experimental. External implementation interoperability and independent format certification remain pending. Decoy/duress functionality is deferred and no plausible-deniability claim is made.
