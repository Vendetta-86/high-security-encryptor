# v0.7.0

**Status: release candidate pending exact-tag Windows build and packaged ZIP acceptance.**

This cumulative stable release consolidates the completed HSE2 v2/v3 workflows and the isolated HSE2 v4 two-view candidate. The prior v0.6.0–v0.6.4 roadmap checkpoints are included as one cumulative release to avoid publishing indistinguishable builds.

## Highlights

- HSE2 v2/v3 password, keyfile, DPAPI, wrapper management, header backup, access destroy, encrypted manifest, and GUI workflows.
- Experimental HSE2 v4 fixed-capacity two-view container with isolated codecs, file workflows, CLI create/open/replace commands, and GUI actions.
- v4 automation accepts passwords through masked prompts or redirected stdin; credentials are not placed in command arguments or logs.
- v4 replacement writes a new output and preserves the other view. The format does not claim plausible deniability.

## Validation

- Full local suite: 712 passed, 6 skipped.
- HSE2 v4, GUI, and Windows release-contract focused checks: 120 passed with PyCryptodome 3.20.0.
- Local PyInstaller CLI and HSE2 GUI onefile builds and v4 create/open/replace smoke passed.
- `pip-audit`, `compileall`, YAML parsing, and `pre-commit run --all-files` passed before release packaging.
- Exact-tag GitHub Actions Windows ZIP build, all ten executable checks, artifact verification, and release publication are pending.

## Scope and limitations

HSE2 v4 is an experimental two-view format. Do not use it to claim plausible deniability. Decoy/duress functionality remains deferred. Existing v2/v3 formats remain unchanged.
