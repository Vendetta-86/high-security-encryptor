# v0.6.0-alpha.8

**Status: release candidate preparation; not published.**

This alpha packages the current HSE2 archive workflows after `v0.6.0-alpha.7`.

## Highlights

- Adds HSE2 v3 streaming archive support while retaining v2 read/write compatibility.
- Adds authenticated archive validation, including a standalone Windows helper executable.
- Extends the HSE2 GUI with create, restore, validate, metadata preview, masked in-memory password entry, and a guided create-to-restore path.
- Allows restore staging to use `HSE2_RESTORE_TEMP_DIR` when it is an existing directory on the same filesystem as the restore destination.
- Records the Phase 8 decoy/duress feature as deferred pending a separate format proposal and independent cryptographic review. This alpha makes no plausible-deniability claim.

## Validation status

The local Windows 11 x64 development checkout passed 669 unit tests with 6 skipped after adding strict rejection of JSON booleans in integer-valued HSE2 headers, header-backup metadata, payload chunk indices, and archive manifest fields, along with `pre-commit`, `compileall`, and `pip-audit`. All ten Windows executables were rebuilt; CLI smoke checks passed; a packaged v3 create/inspect/validate/open round trip restored byte-identical content. The rebuilt packaged HSE2 GUI inspected a disposable v3 archive and returned exit code 0 with a non-secret metadata summary. The refreshed 16-entry local ZIP was assembled and its contents checked. Initial parser fix commit `45e7e4c` passed [GitHub Actions CI](https://github.com/Vendetta-86/high-security-encryptor/actions/runs/41180527122) on Windows Python 3.11, 3.12, and 3.13. CI for the additional integer-boundary hardening and maintainer release review remain outstanding.
